## 1. Introduction & Deployment Options

DocXPilot is a Python-based CLI application designed for project analysis, documentation generation, and AI-driven insights. It leverages various analyzers (Git, code, activity, etc.) and integrates with AI models (Gemini) to provide comprehensive project reports and synthetic data generation.

Given its nature as a CLI tool with AI/ML components, deployment typically involves setting up a Python environment and ensuring access to external AI services.

**Deployment Options:**

*   **Standard Deployment:** Direct installation on a server or local machine, ideal for development, testing, or environments where direct system access is preferred.
*   **Docker Deployment:** Containerized deployment using Docker, offering portability, isolation, and easier management of dependencies. This is recommended for production environments.

## 2. Prerequisites & Server Requirements

### 2.1. Operating System

*   Linux (Ubuntu, CentOS, Debian recommended)
*   macOS
*   Windows (for local development/testing)

### 2.2. Software Prerequisites

*   **Git:** Required to clone the repository.
*   **Python:** Version 3.9 or higher.
    *   Verify with: `python3 --version`
*   **pip:** Python package installer.
    *   Verify with: `pip3 --version`
*   **venv (optional but recommended):** For creating isolated Python environments.
*   **Docker & Docker Compose (for Docker Deployment):**
    *   Verify with: `docker --version`, `docker compose version`

### 2.3. Hardware Requirements

The hardware requirements for DocXPilot can vary significantly based on the size and complexity of the projects it analyzes, as well as the intensity of its AI/ML tasks.

*   **CPU:**
    *   **Minimum:** 2 Cores
    *   **Recommended:** 4+ Cores (for faster analysis and AI model inference/training)
*   **RAM:**
    *   **Minimum:** 4 GB
    *   **Recommended:** 8 GB or more (especially when dealing with large codebases, extensive knowledge bases, or running ML training tasks).
*   **Disk Space:**
    *   **Minimum:** 10 GB (for project files, dependencies, and temporary output).
    *   **Recommended:** 50 GB or more (if storing large datasets, ML models, or numerous generated reports).
*   **GPU (Optional):** While not strictly required for all operations, if the `ml` module's `torch` components are configured to use GPU acceleration, a dedicated GPU (NVIDIA with CUDA) will significantly speed up training and inference tasks.

# DocXPilot Deployment Guide

This document provides a comprehensive guide for deploying DocXPilot, a Python project designed for generating comprehensive project documentation.

## 1. Introduction & Deployment Options

DocXPilot is a Python-based application that analyzes project structures, code, and activity to generate comprehensive reports and documentation. It integrates with AI models (specifically Gemini) for enhanced content generation and insights.

Given its nature as a CLI tool with AI/ML components, deployment typically involves setting up a robust Python environment and ensuring secure access to external AI services.

**Key Deployment Options:**

*   **Standard Deployment (Manual/Direct):** Installing and running DocXPilot directly on a server or local machine. This method offers fine-grained control and is suitable for development, testing, or environments with specific customization needs.
*   **Docker Deployment:** Containerizing DocXPilot using Docker. This approach provides portability, isolation from the host system, simplified dependency management, and consistent environments across different stages. It is generally recommended for production and scalable deployments.

---

## 2. Prerequisites & Server Requirements

### 2.1. Operating System

*   **Linux:** (e.g., Ubuntu 20.04+, CentOS 7+, Debian 10+) - **Recommended for production.**
*   **macOS:** For development and testing environments.
*   **Windows:** For development and testing environments.

### 2.2. Software Prerequisites

*   **Git:** Required to clone the DocXPilot repository.
    *   Installation (Ubuntu): `sudo apt update && sudo apt install git`
    *   Verification: `git --version`
*   **Python:** Version 3.9 or higher.
    *   DocXPilot relies on modern Python features and libraries.
    *   Installation (Ubuntu, if not pre-installed): `sudo apt update && sudo apt install python3.9 python3-pip python3.9-venv`
    *   Verification: `python3.9 --version` (or `python3 --version` if 3.9 is default)
*   **pip:** Python package installer.
    *   Usually installed with Python.
    *   Verification: `pip3 --version`
*   **venv (Python virtual environments):** Highly recommended for isolating project dependencies.
*   **Docker & Docker Compose (for Docker Deployment):**
    *   Follow official Docker installation guides for your OS.
    *   Verification: `docker --version`, `docker compose version`

### 2.3. Hardware Requirements

## 4. Standard Deployment (Manual/Direct)

This section outlines the steps for deploying DocXPilot directly on a Linux server.

### 4.1. Step 1: Clone the Repository

```bash
# Navigate to your desired deployment directory
cd /opt

git clone https://github.com/yk-kumawat/DocXPilot.git
cd DocXPilot
```

### 4.2. Step 2: Set up a Python Virtual Environment

It's highly recommended to use a virtual environment to isolate project dependencies.

```bash
# Create a virtual environment
python3.9 -m venv venv

# Activate the virtual environment
source venv/bin/activate
```

### 4.3. Step 3: Install Dependencies

Install all required Python packages listed in `requirements.txt`.

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4.4. Step 4: Configure Environment Variables

Create a `.env` file in the project root (`/opt/DocXPilot/.env`) and populate it with the necessary environment variables.

```bash
# Create and edit the .env file
nano .env
```

Add the following content (replace with your actual key):

```ini
GEMINI_API_KEY=YOUR_GEMINI_API_KEY_HERE
```

Save and exit the editor.

### 4.5. Step 5: Run the Application

DocXPilot is a CLI tool. You can run its `main.py` script directly.

```bash
# Ensure you are in the project root and virtual environment is active
cd /opt/DocXPilot
source venv/bin/activate

# Example: Run the main application (this will show the CLI interface)
python3 src/main.py

# To run a specific command, e.g., to analyze a project
# python3 src/main.py analyze --path /path/to/your/target/project
```

### 4.6. Step 6: Process Management (Optional, for continuous tasks)

If DocXPilot were to evolve into a service or run long-running background tasks, you would typically use a process manager like `systemd` or `Supervisor` to ensure it runs continuously and restarts on failure. As a CLI tool, this is less common, but a `systemd` service file could be created to run specific DocXPilot commands on a schedule or as a daemon.

**Example `systemd` service file (`/etc/systemd/system/docxpilot.service`):**

```ini
[Unit]
Description=DocXPilot Background Task
After=network.target

[Service]
User=your_user # Replace with a dedicated service user
Group=your_group # Replace with a dedicated service group
WorkingDirectory=/opt/DocXPilot
EnvironmentFile=/opt/DocXPilot/.env
ExecStart=/opt/DocXPilot/venv/bin/python3 /opt/DocXPilot/src/main.py <your_command_here>
Restart=on-failure
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

Reload systemd, enable, and start the service:

```bash
sudo systemctl daemon-reload
sudo systemctl enable docxpilot.service
sudo systemctl start docxpilot.service
sudo systemctl status docxpilot.service
```
